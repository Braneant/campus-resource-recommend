# 01 · 数据库设计（MySQL 业务库）

> 系统：基于知识图谱 + 协同过滤算法的校园学习资源推荐平台
> 数据库：MySQL 8.x（字符集 utf8mb4 / 排序规则 utf8mb4_0900_ai_ci）
> 访问层：MyBatis-Plus
> 配套文档：`02-知识图谱设计.md`（Neo4j）、`03-接口契约.md`（API）

---

## 一、设计总则

1. 主键：所有业务表统一使用 `BIGINT AUTO_INCREMENT` 自增主键 `id`，便于分表与关联。
2. 外键约束：MySQL 层不强制物理外键（避免跨库与级联锁问题），使用逻辑外键 + 索引保证关联与查询性能；关联字段命名统一为 `xxx_id`。
3. 时间字段：`create_time`、`update_time` 统一 `DATETIME DEFAULT CURRENT_TIMESTAMP`，`update_time` 增加 `ON UPDATE CURRENT_TIMESTAMP`。
4. 软删除：本系统采用 `status` 字段标记状态（0/1/2），不使用物理删除，保证行为数据可追溯（ItemCF 依赖历史行为）。
5. 编码风格：表名小写下划线；`resource_no` 作为学习资源在 MySQL 与 Neo4j 之间的唯一关联键（对应 Neo4j `Resource.resource_id`）。
6. 三路推荐支撑要点：
   - ItemCF 协同过滤 → 由 `favorite_behavior` / `download_behavior` / `rating_behavior` 三张行为表共同构成「用户-资源」隐式反馈矩阵（详见 §三）。
   - 热度加权 → `learning_resource` 的 `view_count / download_count / avg_rating / heat` 字段。
   - 知识图谱语义关联 → `learning_resource.primary_kp_id` 冗余指向知识点，真正的多跳语义关系存于 Neo4j（见 `02-知识图谱设计.md`）。

## 三、行为表与 ItemCF 的对应设计

ItemCF（基于物品的协同过滤）核心公式（余弦相似度）：

```
sim(i, j) = Σ_u (r_ui · r_uj)  /  ( √(Σ_u r_ui²) · √(Σ_u r_uj²) )
其中 r_ui 为用户 u 对资源 i 的"综合隐式反馈分值"
```

综合隐式反馈分值计算（后端离线任务定时计算，可落临时表或内存）：

| 行为 | 表 | 分值贡献 | 语义 |
|------|-----|---------|------|
| 收藏 | favorite_behavior | `w_fav = 1.0` | 强意愿 |
| 下载 | download_behavior | `w_dl = 0.8` | 中强意愿 |
| 评分 | rating_behavior | `w_rate = score / 5.0`（1~5 分） | 显式偏好 |

> 单用户对同一资源的综合分 `r = max` 或 `加和` 后截断到 [0,1]（建议：取三路加权之和再 min-max 归一化）。

为什么拆成三张表
- 评分是显式 1~5 分，收藏/下载是布尔隐式反馈，量级不同，分表存储语义清晰、便于分别统计与权重调参。
- 每张表以 `(student_id, resource_id)` 建唯一索引，天然去重，避免同一行为重复刷分。

ItemCF 需要用到的索引：
- `idx_resource_id`：快速取出「对资源 i 有过行为的用户集合 N(i)」。
- `idx_student_id`：快速取出「用户 u 交互过的资源集合」。
- 离线任务扫描全表构建共现矩阵即可，无需复杂联表。

## 四、完整表结构

### 4.1 学院表 `college`

| 字段 | 类型 | 说明 | 约束 |
|------|------|------|------|
| id | BIGINT | 主键 | PK, AUTO_INCREMENT |
| name | VARCHAR(100) | 学院名称 | NOT NULL |
| code | VARCHAR(50) | 学院代码（如 `CS`） | NOT NULL, UNIQUE |
| description | VARCHAR(255) | 简介 | |
| sort | INT | 排序号 | DEFAULT 0 |
| create_time | DATETIME | 创建时间 | DEFAULT CURRENT_TIMESTAMP |

索引：`uk_code(code)` 唯一。

```sql
CREATE TABLE college (
  id           BIGINT       NOT NULL AUTO_INCREMENT,
  name         VARCHAR(100) NOT NULL,
  code         VARCHAR(50)  NOT NULL,
  description  VARCHAR(255),
  sort         INT          NOT NULL DEFAULT 0,
  create_time  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_code (code)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='学院表';
```

### 4.5 学习资源表 `learning_resource`

| 字段 | 类型 | 说明 | 约束 |

| download_count | INT | 下载量 | DEFAULT 0 |

| update_time | DATETIME | 更新时间 | ON UPDATE |

- `uk_resource_no(resource_no)` 唯一（与 Neo4j 关联键）
- `idx_category_id`，`idx_college_id`，`idx_course_id`，`idx_primary_kp_id`
- `idx_status(status)`，`idx_heat(heat)`，`idx_view_count(view_count)`

```sql
CREATE TABLE learning_resource (
  id             BIGINT         NOT NULL AUTO_INCREMENT,
  resource_no    VARCHAR(50)    NOT NULL,
  title          VARCHAR(200)   NOT NULL,
  category_id    BIGINT,
  college_id     BIGINT,
  major_id       BIGINT,
  course_id      BIGINT,
  primary_kp_id  BIGINT,
  type           TINYINT        NOT NULL DEFAULT 1,
  file_url       VARCHAR(255),
  cover_url      VARCHAR(255),
  description    TEXT,
  author         VARCHAR(100),
  uploader_id    BIGINT,
  uploader_type  TINYINT        NOT NULL DEFAULT 1,
  view_count     INT            NOT NULL DEFAULT 0,
  download_count INT            NOT NULL DEFAULT 0,
  favorite_count INT            NOT NULL DEFAULT 0,
  avg_rating     DECIMAL(3,2)   NOT NULL DEFAULT 0.00,
  rating_count   INT            NOT NULL DEFAULT 0,
  heat           DECIMAL(10,4)  NOT NULL DEFAULT 0.0000,
  status         TINYINT        NOT NULL DEFAULT 0,
  audit_time     DATETIME,
  create_time    DATETIME       NOT NULL DEFAULT CURRENT_TIMESTAMP,
  update_time    DATETIME       NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_resource_no (resource_no),
  KEY idx_category_id (category_id),
  KEY idx_college_id (college_id),
  KEY idx_course_id (course_id),
  KEY idx_primary_kp_id (primary_kp_id),
  KEY idx_status (status),
  KEY idx_heat (heat),
  KEY idx_view_count (view_count)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='学习资源表';
```

## 七、字段约定速查

- 所有 `status` 类字段：`0` 通常表示「初始/禁用/待处理」，具体语义见各表。
- 枚举字段统一用 `TINYINT`，值与含义以各表注释为准，前后端共用一份常量字典（见 `03-接口契约.md`）。
- 时间统一 `DATETIME`（不存时区，服务端默认本地时区）。
- 密码统一 BCrypt 加密（60 位，`VARCHAR(100)` 留余量）。
