# 推荐引擎性能测量

执行 `python evaluation/benchmark.py` 复现，完整机器可读结果见 `evaluation/benchmark-results.json`。两组使用相同公开模拟数据、真实 Java 排序引擎和 4 个线程；基线每次重建相似度快照，优化组复用有界 TTL 缓存，运行前检查各用户排序完全一致。每组预热 100 次、计时 400 次；耗时从线程开始执行到引擎返回，不含排队。

本次环境 Windows 11、Java 21、32 逻辑 CPU，192 条已审核资源、20 个评测用户、342 条训练交互。基线 P50 1.684 ms、P95 4.073 ms、约 1959 次/秒；缓存组 P50 0.585 ms、P95 0.746 ms、约 7621 次/秒。这是一次连续实验，吞吐量以整个任务完成时间计算，非稳定容量承诺。

此测量只覆盖进程内计算和缓存命中，不包含 HTTP、MySQL、Neo4j、网络、冷缓存或其他系统的资源竞争；没有多轮置信区间及 GC 隔离，不能当作线上接口的 P95。产品快照缓存默认 30 秒、图谱查询缓存默认 15 秒，相关写事务提交后主动失效；外部直接修改数据库时可能在 TTL 内短暂陈旧。

## 隔离环境的 HTTP 接口对照

2026-11-03 在同一台 Windows 11 主机、32 逻辑 CPU、JDK 21 上测量 `/api/recommend/personal?topN=10`。MySQL 8 和 Neo4j 2026 使用独立本机端口和临时数据目录，导入仓库模拟数据（200 资源、30 学生、316 图节点）；两次测量均在审核数据更改之前进行，使用同一数据库与图谱状态。优化前为提交 `2f11d96`，优化后为提交 `f18b306`；各执行 20 次预热，4 个并发线程、200 次请求，计时从客户端线程开始发送到收到响应，包含 HTTP 往返及服务端处理，不含客户端线程池排队；P95 只对成功请求统计，任何失败会中止测试。缓存命中时不一定访问数据库或 Neo4j。

| 版本 | P50 | P95 | 吞吐 |
| --- | ---: | ---: | ---: |
| 优化前 | 90.782 ms | 125.202 ms | 41.66 请求/秒 |
| 优化后 | 10.900 ms | 29.749 ms | 293.60 请求/秒 |

这是一轮预热后的本机小规模模拟数据测试，优化后包含快照缓存命中；结果不包含冷启动表现、跨机器网络或线上真实流量，不能作为线上容量保证。脱敏原始数据见 `evaluation/http-results.json`；通过环境变量 `CAMPUS_BENCH_USER`、`CAMPUS_BENCH_PASSWORD` 提供临时测试账号，使用 `python evaluation/http_benchmark.py --base http://127.0.0.1:<隔离后端端口> --confirm-disposable` 复现。脚本严格限制 IPv4 回环并禁用重定向；回环地址本身不能证明目标数据库隔离，操作者仍须核实。
