# 工程完善记录

- 账号：找回密码使用邮件投递的随机凭证，凭证哈希保存，具备有效期和单次消费保护；登录和已有令牌检查账号状态。
- 推荐：按加权贡献标记来源，保留排序精度；离线评测与产品共享 Java 排序引擎。
- 审核：MySQL 写入事务化，图谱同步使用持久化记录、状态查看与重试；资源级锁确保并发操作的顺序。
- 交付：增加端口避让启动器、自动化测试与 CI、模拟数据评测和进程内基准。
- 局限：重置密码依赖配置真实 SMTP；当前评测为模拟数据，性能基准不含网络及数据库；演示视频如使用模拟接口会明确标记。
- 密码找回对账号不匹配、冷却与投递失败统一响应，并按客户端地址实行进程内限流。SMTP 使用单线程、100 项容量的异步队列，排队满时统一提示繁忙；验证码仍在独立事务中签发并由 SMTP 投递。队列仅驻留本进程，进程退出会丢失待处理请求；多实例部署需在网关实施共享限流，并使用持久队列和集中监控。异步化降低 SMTP 执行时间泄漏，但没有对所有可观察时序进行安全证明。
- 依赖审计：ECharts 升级至 6.1、Vite 升级至 7.3，完整及运行时 npm audit 均报告零漏洞；学生端与管理端图谱使用隔离模拟数据的浏览器渲染检查通过。

详细测试与复现方法见 `docs/quickstart.md`、`docs/evaluation.md` 和 `docs/performance.md`。
